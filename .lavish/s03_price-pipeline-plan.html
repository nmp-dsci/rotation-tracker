Flagged up front

Four things the data says about the design

Each one comes from a read-only pass today over rt.mentions, rt.mention_assets and rt.assets in database rotation, the other eight databases on the central Postgres, the sibling repos, and a live probe of every proxy symbol.

There is no price feed to add to. The right home is a new sibling built on the property repo's loader recommended

You remembered a repo that pulls pricing. The closest is propertyiq_getdata, and it pulls property pricing: NSW sales and rents, ABS and RBA series, landed as raw → staging in database propertyiq by a manifest-driven loader and dbt. That loader is exactly the machinery a daily stock feed needs (partitioned CSVs with sha256 manifests, incremental COPY, dbt tests, meta.pipeline_runs), but US market prices do not belong in a database called propertyiq, run by the property script. The other candidate, value-invest-agent, has a good yfinance loader (market/yahoo.py, market/fred.py) that writes parquet and a DuckDB file nobody else can read. The proposal: a new repo market-getdata that copies the property repo's core/, db/ and dbt/ skeleton and value-invest-agent's two fetchers, owns database market on the central Postgres, and serves every project over postgres_fdw, the way data-qa-agent already reads propertyiq_staging. Decision 1 below.

A proxy is not always a ticker. Three proxy types, and an honest none

Of the 23 unpriced assets, 13 are macro words: recession (177 rows), inflation (130), liquidity (44), jobs (32). What prices a recession call is the 10-year minus 3-month Treasury spread, a FRED series, not an ETF. Defensives (196 rows, the biggest gap) is three sectors at once, so it is an equal-weight basket of XLP, XLU and XLV. So proxy grows a type: yahoo:IGV, fred:T10Y3M, basket:defensives. Five assets stay none on purpose (tariffs, geopolitics, earnings, US debt, stablecoins): a sentence about tariffs is context for other calls, not a call with a price. Decision 4 lists every fill.

"Software" has three different component lists. Ship two now, the third later

The tickers inside a category can come from GICS (the S&P 500 list we already hold: 14 Application Software and 7 Systems Software names), from the proxy ETF's holdings (IGV holds about 120 names, published daily by the issuer), or from what he actually says (MSFT 69 mentions, PLTR 41, ORCL 20, ADBE 6, CRM 6, CRWD 3; MSFT and CRWD are "systems", the rest "application"). GICS and his names are already in rt.assets and rt.mention_assets, so the Chart and Asset pages can show components in this branch with no new source. Issuer holdings need one scraper per issuer (State Street, iShares and VanEck cover 45 of the 60 ETF proxies) and are phase 2. Decision 6.

Point in time, or the later measurement is wrong by construction

Four rules, carried from AGENTS.md into the schema. A Saturday wrap is tradable at Monday's open, never Friday's close. Prices are stored unadjusted and adjusted (Yahoo gives both when auto_adjust=False) with splits and dividends as rows, so a 2024 call on NVDA is judged on the shares that existed then. Index membership is a dated snapshot, so a name that joined the S&P 500 in 2025 is not in its 2023 universe. FRED revises history, so each pull is an asof= vintage appended, never an edit, the same rule the ABS series already follow. Three ETF proxies started after the first wrap (MAGS Apr 2023, IBIT Jan 2024, the Trump coin Jan 2025); each gets a basket or a stated gap, not a silent zero.

A note on Bonds & yields: a bullish call there is bullish on whatever he named, so "yields going higher" is bullish on the yield and bearish on TLT. Pinning the theme to the yield (DGS10) and keeping TLT as the companion lets the measurement branch score either reading; it does not decide for it.

The choice is reversible at no cost: Yahoo serves the full history on request, so extending a start date later is one backfill run, not a migration.

Where the pipeline lives

Three homes for a daily price feed; one keeps every repo doing one thing

The shape of each, with what it costs. Decision 1 picks.

A · New sibling market-getdata, the same setup as propertyiq_getdata recommended your note: yes

Clone the property repo's skeleton (core/manifest.py, core/snapshot.py, db/load.py, db/registry.py, the dbt project and db init / update / smoke), drop in value-invest-agent's yahoo.py and fred.py as sources/, add sources/holdings.py later. Registry entry P12: database market, roles market_owner and market_ro, make db-init, a zero-cost smoke.

Consumers. rotation-tracker, value-invest-agent (can retire its DuckDB loader), anything later. Each imports market_staging.* over postgres_fdw as market_ro, exactly as data-qa-agent imports propertyiq_staging (migration 0040).

Costs. One more repo and launchd job to look after. Half a day of agent work for the scaffold, registry and first load before any price lands.

Gets right. A database named for what it holds, its own daily cadence, and the public rotation-tracker repo stays free of a price loader.

B · Extend propertyiq_getdata

Add sources/yahoo.py and sources/fred.py to the property repo; land in database propertyiq as raw.yahoo_prices, staging.prices_daily; append to update_data_and_push.sh.

Consumers. Connect to propertyiq for US stock prices, forever.

Costs. Least new code (two source modules, a LoadSpec each). The property script runs weekly for the NSW files and would now carry a daily job; the repo's name, README and registry notes all become wrong.

Gets right. Reuses the loader without copying it.

C · Inside rotation-tracker (rt.prices)

What the s00 plan said in January: copy the yfinance loader into this repo, rt prices update, tables in schema rt.

Consumers. Only this project. value-invest-agent keeps its own copy; the next project copies again.

Sizing and cadence

  • Backfill. Proxies, indexes and FRED series from their first date (71 of 89 proxies start before 2015; ^IRX from 1960). The 518 constituents and his named stocks from 2015-01-01: eight years before the first wrap, enough for any lookback the measurement will want, and 314 of today's 503 S&P 500 members were already in the index by then (371 by 2018, 424 by 2022), so the list is still mostly the index he talks about. About 2.3 M price rows, ≈ 300 MB with indexes. The probe today pulled 89 full histories in under two minutes with a 0.3 s pause; the full backfill is 15 to 25 minutes.
  • Daily. yfinance.download() in batches of 100 symbols: about ten requests, 750 rows, a few seconds. FRED: 18 small CSVs. db update copies only partitions whose sha256 changed (the current year's file per symbol), then dbt build.
  • When. US cash close is 16:00 New York, 07:00 or 08:00 Sydney the next morning. A 09:00 Sydney run every day catches it; weekends and US holidays land nothing and exit clean. launchd on this Mac, the pattern productivity-tracker already uses (~/Library/LaunchAgents/com.nmp-dsci.pt-refresh.plist): com.nmp-dsci.market-update.plist, log under ~/.market/. Weekly, Saturday: constituents and (later) holdings.
  • Audit. market-getdata audit lists symbols whose last price is more than three business days old, series whose vintage did not advance in a week, baskets with a missing member, and the resolver's new unknown symbols. Printed, and written to meta.pipeline_runs.
  • Secrets. None for Yahoo or FRED. The database URL is the P12 block of nmp-central-ai/.db-urls.env pasted into .env, as every project does; never hardcoded. data/ is gitignored: prices are never committed, in either repo.
How the two repos meet

The tracker stays about the channel; it reads prices, it never fetches them

In rotation-tracker, this branch

  • assets/proxies.yaml (v2): every asset's primary series and companions, typed. rt assets seed writes rt.asset_proxies; the old proxy column stays as the primary's symbol for compatibility.
  • assets/components.yaml: GICS sub-industry → category. rt assets components <id> prints a category's three lists.
  • sql/00x_market_fdw.sql: CREATE EXTENSION postgres_fdw (declared in the registry for rotation), server market, user mapping market_ro, IMPORT FOREIGN SCHEMA staging … INTO market_staging. Run by rt db migrate.
  • Viewer: the Chart row gains the price line under the mention lines on the same x scale (view assets first; the keyword view maps through the table above); the Asset page gains "Components" and "Priced by IGV since 2001". /api/chart and /api/assets/:id read market_staging through the store, with a fixture-backed fake in tests. The design lint stays green: price lines use --accent, stance keeps green and red.
  • rt assets export-symbols writes the list the feed should fetch, committed into market-getdata/instruments/rotation-tracker.txt, so the feed never imports tracker code.

Not in this branch

  • Measuring calls against prices (forward returns at 1, 4, 13, 26 and 52 weeks from the Monday open after the wrap, against SPY; the rotation in/out sign check). That is the branch after this one, on the tables this one creates.
  • Issuer holdings, constituent change history, net liquidity, CoinGecko totals: phase 2 of the feed, its own branch in market-getdata.

Risks and failure modes

What can go wrong, and the guard for each

RiskWhat it would doGuard
Yahoo is unofficialyfinance scrapes an undocumented API; it has broken for days before, and bulk pulls get rate-limited.Batched requests with a pause; audit flags staleness; the loader is source-agnostic, so a second source (Stooq's free CSV, or Tiingo with a free key) is one more sources/ module writing the same partitions.
A proxy starts lateMAGS (Apr 2023), IBIT (Jan 2024), WGMI (Feb 2022), TRUMP (Jan 2025) have no price for early wraps; a naive join scores those calls as zero.Baskets for mag7 and crypto; asset_proxies.from is explicit; the measurement joins on date ≥ from and reports calls it could not price rather than dropping them silently.
SurvivorshipToday's S&P 500 list is not 2023's; a component list drawn from it flatters the index.Dated constituent snapshots from day one; the change-history table in phase 2 extends them backwards.
Adjusted vs unadjustedScoring a 2024 NVDA call on post-split adjusted prices is right for returns and wrong for "it was at $900".Both closes stored; splits and dividends as rows; the measurement uses adj_close for returns and close for quoted levels.
RevisionsFRED revises claims and CPI; a backtest that reads today's values saw numbers nobody had at the time.asof= vintages appended, never edited, same as the ABS series; the point-in-time read takes the vintage available on the call's date.
Symbol driftTickers change (FB → META), spin-offs appear (SNDK, Feb 2025), ADRs delist.instruments keeps first_date and last_date; audit lists symbols that stopped; a delisted name keeps its rows.
TimezonesYahoo dates are exchange-local; FRED dates are US; a wrap is published on a Sydney Saturday.All dates stored as calendar dates in the exchange's zone; the tradable-at rule (Monday open) lives in one function in the tracker and is tested.
Two public reposA price file or a manifest with 2.3 M rows ends up in git.data/ gitignored in market-getdata; the tracker holds only yaml and SQL; tests use synthetic fixtures; CI uses the throwaway Postgres service the platform prescribes.
The Mac is asleepA launchd job on a laptop misses mornings.Idempotent update catches up on the next run (Yahoo returns the missing days); audit says how far behind. Moving the job to the platform's AWS stack is configuration only, once that exists.
